🎬 Video production workflow

How this interview becomes a finished video, from raw footage to published posts. AI does the reading and choosing, code does the exact work, a human approves. Each step is documented, versioned, committed and pushed.

1Plan and set rulesdone

Probe the source (4K, 28 min), decide the pipeline, no media in git, document and push every step.

Tools ffprobe, gitOutput docs/PLAN.md, CLAUDE.mdAI role Claude plans; user sets rules
2Extract audio and transcribedone

16 kHz audio, word timestamps, live ETA while running (about 2 min).

Tools ffmpeg, mlx-whisper large-v3-turboOutput transcript.raw.jsonAI role Whisper (local, free)
3Correct the transcriptdone

17 reviewed rules (names, products); raw kept; speakers: Marianna asks, Rifat Erdem Sahin answers.

Tools data/corrections.jsonOutput transcript.json / .txtAI role Claude + user review
4Subtitles and chaptersdone

Cues from word timing (42 chars/line, 2 lines). Chapters anchored by exact phrases.

Tools 03_make_subtitles, 04_make_chaptersOutput SRT/VTT, cues, 13 chaptersAI role Claude segments topics
5Proxy and clean audiodone

720p proxy for fast edits; dialogue cleaned (speech-to-noise gap 28 to 44 dB), -16 LUFS.

Tools ffmpeg h264_videotoolbox, afftdn + gate + loudnormOutput work/proxy.mp4 (not in git)AI role Code, measured
6Decide the cutsdone

Edit decision list in source time; pre/post-roll and long pauses out; 8 duplicate ideas removed (159 s) with proof-read joins.

Tools 07_plan_cuts.pyOutput cuts.json, TIMELINE.mdAI role Claude picks; code enforces
7Highlights and platform cutsdone

Hook-first highlights reel; a separate LinkedIn cut capped at 14:00 with context for every section.

Tools 07_plan_cuts.pyOutput Highlights 0:53, LinkedIn 12:36AI role Claude picks the claims

15Governdone

Every step documented, versioned, committed and pushed; keys only in .env; costs tracked.

Tools version.py, CHANGELOG, DECISIONS, pre-commit hookOutput v0.x tags, snapshotsAI role Code + Claude

Rules that apply to every stage

  • No video or audio in git (metadata and code only)
  • Keys only in .env, never committed
  • Document the rationale for each step, then commit and push
  • Always create the timeline, always version, always three thumbnails
  • Measure instead of guessing (audio levels, durations); proof-read every cut join
  • Cheap models first; cache everything; log the cost
